# 视觉与动画：先统一尺度，再扩充素材

在建立视觉样片、制作角色/精灵资源或处理移动、大小、闪烁、滑行问题时读取。

## 参考与世界

先实际查看现有参考图。游戏截图负责镜头、角色世界比例、像素密度、地形高差、前中后景、光照和战斗构图；角色设计稿负责发型、服装、职业、配色及魅力，不能直接决定游戏内头身与大小。没有收到的“六人角色图”等资料不得假设已见过。

将选定的镜头参数、角色相对门窗/台阶的比例、像素密度、渲染过滤与颜色规范记录到项目状态或资源配置。参考商业游戏的视觉语言，不复制拆包素材；第三方资源保留来源与许可证。

HD-2D 场景至少形成清晰活动区、近景遮挡与远景层次，利用道路、高差、建筑、植被和生活道具组织密度；密度不能牺牲通行辨识。玩家区域清晰，景深、辉光和雾服务空间感。夜景采用冷环境与暖灯窗；雪景改变地表与植被，洞穴靠结构和局部光，战斗在有环境层次的舞台中呈现。

按实际 Godot 版本、渲染器及目标硬件选用后处理；确认兼容性，不把不存在或未启用的效果写成已完成。支持回退时保持构图和可读性，并披露差异。

## 资源与动画契约

对主角、NPC、精灵建立共享的资源约定：帧矩形、画布、脚底/接触点、朝向、原始像素到世界单位的比例、阴影锚点，以及需要时的身体参照点。所有 idle/walk/run 和方向使用同一尺度基准。

- 图集先检查真实行列边界和边距，再切片；不假设生成图被等分后每格都完整。检查邻帧头发、尾巴等串入，纹理过滤和图集边缘渗色。
- 检查真实 alpha 通道。棋盘背景可能已经画进 RGB，提示词“透明”不是透明证据。去背景时保护眼白、白毛、半透明特效；不能盲目删除所有白/灰像素。
- 可见范围检查使用与实际渲染方式相符的阈值；抗锯齿软透明资源可另列主体和弱透明边缘。不要让微弱噪点决定整个人物的缩放。
- **不能逐帧按包围盒重新缩放人物。** 固定像素/世界单位和注册点，以头、躯干等稳定参照检查体型。耳朵摆动、尾巴展开、跳跃会自然改变外接矩形，不能为“高度一致”把动作拉伸变形。
- 不同来源的 idle/run 图集先按身体比例校准到统一资源规范，再用于运行时；画布相同不代表主体一样大。必要时修正素材，而非运行时每帧自适应缩放。
- 人物立绘与世界角色保持头发、服装、配色、饰物及身份一致；所有方向和状态保持角色身份。

## 走路、奔跑与跟随

动画应含可辨识的落脚、支撑、换步/腾空与回收姿态；不能只平移一张静图或做整体上下抖动。飞行/漂浮生物使用合理的对应动作。

由**碰撞处理后的实际移动量或速度**驱动步态、朝向和落脚事件，帧率变化不改变步速。挡墙持续按键时不能原地狂跑并播放脚步。停止时落到合理站姿，保留朝向；启动/停止可加小阈值避免抖动。

宠物跟随需要合理的跟随距离、起跑/停步不同阈值、避障或可达路径和追赶速度。追赶不能穿墙；距离过大时使用明确的安全重定位规则，避免频繁瞬移。行走和奔跑按实际运动切换，传送不累计步态里程。转向不能闪烁，暂停、对话和战斗切换要停止相应运动与声音。

## 视觉验收方法

在正常游戏镜头中检查，不只看放大的图集。录制或连续截取“静止 → 起步 → 匀速 → 转向 → 碰撞停住 → 停步 → 再起步”，至少覆盖全部已支持方向和共享代码影响的物种。对比脚底、头/躯干参照、阴影、屏幕位置与动作节奏；用逐帧叠图帮助定位，最终仍看连续播放。

额外验证天然异色、印记、特效叠加，以及世界/战斗/队伍展示间的比例。检查白天、夜晚、遮挡、不同帧率下的闪烁与可读性。固定镜头、位置、时间和光照做修复前后对照，避免通过换角度掩盖问题。

明显不符合参考类别或仍有大小跳变时，继续修复该问题再扩展内容。没有真实运行画面时，只能声称完成静态资源检查。
