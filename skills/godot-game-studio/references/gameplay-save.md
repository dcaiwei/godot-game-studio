# 玩法深度、经济与存档

用于新游戏闭环设计、评估“是否完善”以及继续完善玩法。系统数量与完成感分开判断。

## 可玩的目标链

为每段游玩明确：玩家当前目标、可用选择、选择代价、失败反馈、奖励、奖励改变了什么，以及下一目标从哪里获知。默认精灵 RPG 可采用：认识村庄 → 首次捕捉 → 组成互补队伍 → 区域委托 → 环境探索 → 区域挑战 → 阶段结局与后续收集。

“捕捉三只领奖”只是教学，不能作为全部主线。任务奖励应解锁路线、工具、技能或新挑战等有意义结果；避免一切都只加金币。评估目标时长须依据实际游玩记录，不能由地图数或文字量推算后宣称已经验证。

| 维度 | 判断依据 | 应修复的薄弱设计 |
| --- | --- | --- |
| 探索 | 有地标、线索、路径选择、发现与回报 | 整张图开始即可见全部内容 |
| 收集 | 栖息地/时间/天气可理解，捕捉有准备与取舍 | 全物种随处刷、最高级球永远最优 |
| 成长 | 技能或队伍用途发生变化 | 升级只线性增加数字 |
| 队伍 | 普通物种也有定位与对策 | 稀有全面压制、速度决定一切 |
| 战斗 | 玩家需要考虑资源、状态、换人和敌人意图 | 永远按最强招，敌人只看能量够不够 |
| 长期目标 | 阶段完成后有明确挑战或收集方向 | 教学结束即失去目标 |

先让已有物种拥有互补定位、技能与环境价值，再增加更多物种。展示的特性/性格须影响实际机制，否则清楚标为纯描述，不宣传其策略价值。敌方决策根据自身状态、目标状态、收益与资源选择合理动作，给玩家可理解的线索。

## 经济与公平性

列出主要收入、消耗、解锁时间与可重复奖励；比较训练、探索、任务和挑战的单位时间收益。防止无限低风险训练迅速买光稀有球。用首次奖励、合理递减、进度门槛或对应难度解决，不能只无依据地涨价。

任务领奖、商店交易、捕捉消耗、战斗结算应是一次事务：不能重复输入/重进界面/读档导致重复奖励或多扣资源。满队伍/满收藏需要明确去向或预检，不得吞掉刚捕获的个体。正式玩法不能意外暴露调试赠币、无限道具和随意变天。

捕捉概率做上下界与情境测试；印记球合法命中必获，但扔歪、不合法目标和障碍物不能误判成功。每只个体的稳定身份和随机属性在应保存时固化，避免非预期读档重掷。

## 战斗状态与针对性测试

统一动作验证、资源消耗、效果结算、回合推进、持续状态及胜负结算，减少按钮各自执行半套逻辑。合法动作如何消耗回合对玩家明确；非法动作不消耗资源或推进回合。

至少覆盖实际实现的高风险路径：

- 主动换人后新单位被击倒、自动换人、最后一只倒下，以及队伍仍有健康成员时不能误判全队败北。
- 同归于尽、回合末伤害、治疗满血/濒死、零能量、速度平局；明确定义结算顺序。
- 防御持续时间、状态到期、能量恢复时机与换人后的效果归属；没有幽灵回合或永久增益。
- 胜利、逃跑、失败恢复的奖励与代价；不能反复结算或卡死。失败后能合理回到玩法循环。
- 玩家实际看到的技能说明、概率和消耗与代码一致。

用固定随机种子和边界输入验证具体规则，再通过正常输入走完整场战斗。自动模拟可发现优势策略，不能代替体验判断；不要为简单可逆改动堆砌只复述实现的测试。

## 存档完整性

存档包含版本、进度/任务及领奖状态、收藏个体、队伍引用、背包与货币、解锁、必要的世界状态、位置和设置。持久化影响个体身份与数值的原始数据，加载时校验引用和派生数据，避免共享模板被某只个体修改。

使用安全写入策略与可恢复备份，校验失败时向玩家说明恢复结果；坏档不能静默覆盖好档。支持已有存档的兼容或迁移，保持稳定 ID，不因调整数组顺序改变旧个体物种。无存档、旧档、损坏档和缺失资源均有清楚处理。

自动测试使用隔离存档目录，不覆盖用户真实进度。验证“捕捉带异色/印记个体 → 编队 → 成长 → 领奖/购买 → 保存 → 关闭进程 → 重启读档”，检查数据、外观与一次性奖励标志全部保留。
